IMPLEMENTATION TASK
===================

Project: MediKiosk
Feature: Real AI Clinical Interview Engine using Groq
Phase: AI Clinical Intelligence Integration

IMPORTANT:
Do not treat this as a simple "connect Groq API" task.

The goal is to build a proper adaptive clinical history-taking engine where Groq helps understand patient answers and generate structured information, while our application controls the clinical workflow, question planning, safety rules, and final case structure.

Existing implementation status:

DONE:
- Phase 1.1 — Centralized Types
- Phase 1.2 — Zustand State Management
- Phase 1.3 — Service Interfaces + Service Registry
- Phase 2 — Consent + Language + Input Mode
- Phase 3 — Browser ASR + TTS

The existing project already contains:
- React + TypeScript + Vite
- Zustand
- Patient store
- Doctor store
- AI service abstraction
- Local AI implementation
- ASR service abstraction
- TTS service abstraction
- OCR service abstraction
- Triage service
- CaseSheet service
- FHIR service
- ABDM service
- Service registry
- demo / hybrid / production app modes

DO NOT rebuild the architecture from scratch.

First inspect the existing implementation and integrate into it.

==================================================

Build this pipeline:

PATIENT ANSWER
      ↓
ASR / Touch Input
      ↓
AI SERVICE
      ↓
ANSWER UNDERSTANDING + EXTRACTION
      ↓
STRUCTURED CLINICAL STATE
      ↓
COMPLETENESS CHECK
      ↓
QUESTION PLANNER
      ↓
NEXT QUESTION
      ↓

      ↓

STRUCTURED CLINICAL STATE
      ↓
DETERMINISTIC TRIAGE RULES
      ↓
RED FLAGS / PRIORITY


IMPORTANT ARCHITECTURAL RULE:

Groq must NOT independently control the entire medical interview.

Groq is the language understanding/reasoning component.

Our application remains responsible for:
- clinical structure
- question sequencing
- mandatory information
- complaint-specific branches
- completeness
- safety rules
- triage
- validation
- clinician verification

with:

Verify that no API key appears in:
- source code
- logs
- UI
- Git-tracked files

==================================================
7. EXTRACTION RULES
==================================================

The AI must follow these rules:

RULE 1:
Extract ONLY information explicitly provided by the patient.

RULE 2:
Never invent information.

RULE 3:
Never infer a diagnosis from an answer.

RULE 4:
Never fabricate a medication.

RULE 5:
Never fabricate a symptom.

RULE 6:
Never fabricate a date or duration.

RULE 7:
If the patient does not know something, represent it as unknown/null.

RULE 8:
Preserve the patient's meaning.

RULE 9:
Do not convert uncertainty into certainty.

Example:

Patient:
"I think the pain started yesterday."

Do NOT produce:

"onset: yesterday"

Instead preserve uncertainty appropriately.

Example:

Patient:
"I don't know when it started."

Result:

onset = null

unknownFields includes onset.


==================================================
8. ONE QUESTION AT A TIME
==================================================

The interview must ask ONE question at a time.

Never generate:

"Where is the pain, when did it start, how severe is it and does it spread?"

Instead ask:

"Where exactly do you feel the pain?"

Then after the answer:

"When did the pain start?"

Then:

"How severe is the pain from 0 to 10?"

Then:

"Does the pain spread anywhere else?"


This is essential for:
- voice interaction
- elderly users
- accessibility
- clean structured extraction

The basic logic should be:

↓

↓
Determine complaint
↓

↓

↓

↓

The AI should not keep asking questions indefinitely.

15. AI SYSTEM PROMPT
==================================================

Create a carefully constrained system prompt for Groq.

It should communicate:

"You are the language-understanding component of a patient pre-consultation clinical history system.

Your job is to:
1. Understand what the patient explicitly said.
2. Extract structured clinical information.
3. Identify missing information.
4. Help select the next relevant question within the supplied clinical workflow.
5. Identify possible contradictions.

You are NOT a doctor.
You must NOT diagnose.
You must NOT prescribe.
You must NOT invent patient information.
You must not turn uncertain information into facts.
You must ask one question at a time.
You must follow the supplied clinical question plan.
You must return valid structured JSON only."


Pass the current context separately:

- current ClinicalState
- patient's latest answer
- current complaint
- current question
- allowed question fields
- missing fields
- relevant complaint branch


Do NOT dump unnecessary patient data into every request.
